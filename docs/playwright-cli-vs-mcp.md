## 1. 概要

Playwright には**2つの主要なインターフェース**がある。目的に応じて使い分けることで、開発効率とコストを最適化できる。

```
┌─────────────────────────────────────────────────────────────────┐
│                      Playwright エコシステム                      │
│                                                                   │
│   ┌───────────────────────┐     ┌───────────────────────────┐   │
│   │    Playwright CLI     │     │     Playwright MCP        │   │
│   │                       │     │                           │   │
│   │  開発者がコマンドライン  │     │  AIエージェントがブラウザ   │   │
│   │  で直接操作するツール   │     │  を制御するプロトコル      │   │
│   │                       │     │                           │   │
│   │  対象: 人間            │     │  対象: LLM / AIエージェント │   │
│   │  操作: シェルコマンド   │     │  操作: JSON RPC           │   │
│   └───────────────────────┘     └───────────────────────────┘   │
│                                                                   │
│                  ┌─────────────────────┐                         │
│                  │  Playwright Core    │                         │
│                  │  (ブラウザ自動制御)   │                         │
│                  └─────────────────────┘                         │
└─────────────────────────────────────────────────────────────────┘
```

### 一言での違い

| | Playwright CLI | Playwright MCP |
|---|---|---|
| **何か** | コマンドラインツール | AIエージェント向けプロトコル |
| **誰が使うか** | 開発者（人間） | LLM / AIエージェント |
| **どう動くか** | `npx playwright test` 等のコマンド | JSON RPC でブラウザ操作を送受信 |
| **一言で** | **「手で操作する」** | **「AIに操作させる」** |

## 2. 詳細比較表

| 観点 | Playwright CLI | Playwright MCP |
|------|:---:|:---:|
| **通信方式** | シェルコマンド | JSON RPC（MCPプロトコル） |
| **データフロー** | ディスク（YAML / ファイル） | LLMコンテキスト |
| **トークン消費** | 約27,000 / タスク | 約114,000 / タスク（**約4倍**） |
| **ファイルシステム** | 必須 | 不要 |
| **対話性** | 低（バッチ実行向き） | 高（リアルタイム対話） |
| **AI統合** | 間接的 | ネイティブ |
| **スケーラビリティ** | 高い | コンテキストに制限あり |
| **デバッグ** | Inspector, Trace Viewer | AI分析, スナップショット |
| **CI/CD向き** | ◎ | △ |
| **テスト作成向き** | codegen | 自然言語生成 |

### データフローの違い（図解）

```
【CLI のデータフロー】

  開発者 ──(コマンド)──> シェル ──> Playwright ──> ブラウザ
                                       │
                                       ▼
                              ファイルシステム
                            (テスト結果, レポート,
                             トレース, スクリーンショット)


【MCP のデータフロー】

  ユーザー ──(自然言語)──> LLM ──(JSON RPC)──> MCP Server ──> ブラウザ
                           ▲                       │
                           │                       ▼
                           └─── レスポンス ◄── スナップショット
                          (LLMコンテキスト内で完結)
```

### トークン消費の比較

```
CLI:  ████████░░░░░░░░░░░░░░░░░░░░░░  約 27,000 トークン/タスク
MCP:  ██████████████████████████████░░  約114,000 トークン/タスク

      ← 効率的                    コスト高 →

      CLI は MCP の約 1/4 のトークンで同等タスクを処理可能
```

## 3. 使い分けフロー図

開発ライフサイクルのフェーズに応じて、CLI と MCP を使い分ける。

```
開発ライフサイクルのどのフェーズにいるか？
│
├── テスト設計・計画
│   │
│   └──> 【MCP推奨】自然言語で対話的に設計
│         │
│         └── Planner Agent に要件を伝える
│              │
│              └──> 計画書（.md / .feature）を生成
│
├── テストコード作成
│   │
│   ├──> 【CLI】codegen で操作録画からコード生成
│   │     npx playwright codegen http://localhost:3000
│   │
│   ├──> 【MCP】AIと対話しながらコード生成
│   │     「ログインフローのテストを書いて」
│   │
│   └──> 【Agent】Generator Agent が計画からコード自動生成
│         計画書 → Page Object + テストコード
│
├── テスト実行
│   │
│   └──> 【CLI推奨】コマンドラインで効率的に実行
│         │
│         ├── ローカル:  npx playwright test
│         ├── CI/CD:    GitHub Actions ワークフロー
│         └── 分散実行:  npx playwright test --shard=1/4
│
├── デバッグ
│   │
│   ├──> 【CLI】Inspector / Trace Viewer で視覚的に調査
│   │     npx playwright test --debug
│   │     npx playwright show-trace trace.zip
│   │
│   └──> 【MCP】AIにページ状態を検査させる
│         「このエラーの原因を分析して」
│
└── テスト保守
    │
    ├──> 【Healer Agent】セレクタ自動修復
    │     UI変更を検知 → セレクタを自動更新
    │
    └──> 【MCP】AIにUI変更を分析させる
          「この画面のDOM変更を調べて」
```

## 4. 具体的なシナリオ別推奨

### シナリオA: 「新しいページのE2Eテストを作りたい」

**推奨: MCP --> codegen --> CLI**

```
Step 1                   Step 2                 Step 3                Step 4
┌────────────────┐      ┌────────────────┐     ┌────────────────┐    ┌────────────────┐
│   MCP で        │      │  codegen で     │     │  AIが           │    │  CLI で         │
│   ページ構造を   │ ──>  │  操作を録画し   │ ──> │  Page Object に │ ──>│  テスト実行     │
│   AIに分析させる │      │  ベースコード   │     │  リファクタリング│    │  ・確認          │
│                │      │  を生成         │     │                │    │                │
│  [MCP]         │      │  [CLI]         │     │  [MCP/Agent]   │    │  [CLI]         │
└────────────────┘      └────────────────┘     └────────────────┘    └────────────────┘
```

**手順の詳細:**

1. **MCP** でページ構造をAIに分析させる
   - DOM構造、主要な操作パス、エッジケースの洗い出し
2. **codegen** で操作を録画してベースコードを生成
   - `npx playwright codegen http://localhost:3000/new-page`
3. **AI** が Page Object にリファクタリング
   - 録画コードを保守しやすい形に整理
4. **CLI** でテスト実行・確認
   - `npx playwright test new-page.spec.ts --headed`

---

### シナリオB: 「CIでテストが失敗した」

**推奨: CLI (Trace) --> MCP**

```
Step 1                   Step 2                 Step 3
┌────────────────┐      ┌────────────────┐     ┌────────────────┐
│  show-trace で  │      │  MCP でAIに     │     │  Healer Agent  │
│  失敗箇所の     │ ──>  │  原因分析を     │ ──> │  で自動修復を   │
│  時系列確認     │      │  依頼           │     │  試行           │
│                │      │                │     │                │
│  [CLI]         │      │  [MCP]         │     │  [Agent]       │
└────────────────┘      └────────────────┘     └────────────────┘
```

**手順の詳細:**

1. **show-trace** で失敗箇所の時系列確認
   - `npx playwright show-trace test-results/trace.zip`
   - どのステップで、何が起きたかを視覚的に把握
2. **MCP** でAIに原因分析を依頼
   - ページのスナップショットを取得し、DOM変更を特定
3. **Healer Agent** で自動修復を試行
   - セレクタ変更であれば自動で修正コードを生成

---

### シナリオC: 「リリース前の回帰テスト」

**推奨: CLI**

```
Step 1                   Step 2                 Step 3
┌────────────────┐      ┌────────────────┐     ┌────────────────┐
│  フルテスト     │      │  HTMLレポート   │     │  失敗があれば   │
│  実行           │ ──>  │  生成           │ ──> │  show-trace で  │
│                │      │                │     │  デバッグ       │
│  [CLI]         │      │  [CLI]         │     │  [CLI]         │
└────────────────┘      └────────────────┘     └────────────────┘
```

**手順の詳細:**

1. `npx playwright test` でフルテスト実行
2. `--reporter=html` でレポート生成
3. 失敗があれば `npx playwright show-trace` でデバッグ

```bash
# リリース前回帰テストの実行例
npx playwright test --reporter=html,allure-playwright
npx playwright show-report
```

### シナリオD: 「非技術者にテスト内容を説明したい」

**推奨: MCP + BDD**

```
Step 1                   Step 2
┌────────────────┐      ┌──────────────────────────────────┐
│  MCP でAIに     │      │  出力例（.feature）                │
│  BDDシナリオを  │ ──>  │                                  │
│  生成させる     │      │  機能: ログイン                    │
│                │      │    シナリオ: 正常なログイン          │
│  [MCP]         │      │      前提 ログインページを開く      │
│                │      │      もし 正しい認証情報を入力する    │
│                │      │      ならば ダッシュボードが表示される │
└────────────────┘      └──────────────────────────────────┘
```

**手順の詳細:**

1. **MCP** でAIに BDD シナリオ（`.feature`）を生成させる
2. **Given / When / Then** 形式で非技術者も読める形に整形
3. 必要に応じて Allure Report で視覚的なレポートも生成

## 5. ハイブリッドワークフロー（推奨）

CLI と MCP を組み合わせた**ハイブリッドワークフロー**が、2026年現在の最適解である。

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│              開発フェーズ（MCP中心）                          │
│                                                             │
│    Claude Code + MCP で対話的にテスト作成                     │
│    → テストコードが tests/ に出力                            │
│                                                             │
│    使用ツール: MCP Server, Planner Agent, Generator Agent   │
│                                                             │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│              ローカル検証（CLI中心）                          │
│                                                             │
│    npx playwright test --headed      で動作確認             │
│    npx playwright test --debug       でデバッグ             │
│    npx playwright test --ui          でUI モード            │
│                                                             │
│    使用ツール: Playwright CLI, Inspector, Trace Viewer      │
│                                                             │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│              CI/CD（CLIのみ）                                │
│                                                             │
│    GitHub Actions で自動テスト実行                            │
│    --shard で分散実行（並列化）                               │
│    HTMLレポート + Allure ダッシュボード                       │
│                                                             │
│    使用ツール: Playwright CLI, GitHub Actions               │
│                                                             │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│              保守フェーズ（MCP + Healer）                    │
│                                                             │
│    UI変更 → Healer Agent で自動修復                         │
│    複雑な変更 → MCP でAI分析                                │
│    セレクタ破損 → 自動検知 & 修復提案                        │
│                                                             │
│    使用ツール: Healer Agent, MCP Server                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 7. 2026年のベストプラクティス

### 原則

```
┌───────────────────────────────────────────────────────────┐
│                                                           │
│  1. 必要なMCPのみ接続する（コンテキストタックス回避）         │
│     └── 不要なMCPサーバーは接続しない                       │
│         接続するだけでトークンを消費する                     │
│                                                           │
│  2. 開発 → MCP、実行 → CLI のハイブリッド                   │
│     └── フェーズに応じてツールを切り替える                   │
│                                                           │
│  3. Test Agents を活用して人的コスト削減                     │
│     └── Planner / Generator / Healer の3エージェント体制    │
│                                                           │
│  4. Healer Agent で保守コスト削減                           │
│     └── セレクタ破損の80%を自動修復可能                     │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

### Test Agents 構成

```
┌─────────────────────────────────────────┐
│            Test Agent 体制               │
│                                         │
│  ┌──────────┐  要件定義 / テスト計画     │
│  │ Planner  │  ─── 自然言語 → 計画書    │
│  │ Agent    │      (.md / .feature)     │
│  └────┬─────┘                           │
│       │                                 │
│       ▼                                 │
│  ┌──────────┐  コード生成               │
│  │Generator │  ─── 計画書 → テストコード │
│  │ Agent    │      (Page Object +      │
│  └────┬─────┘       spec ファイル)       │
│       │                                 │
│       ▼                                 │
│  ┌──────────┐  自動修復                 │
│  │ Healer   │  ─── 失敗テスト →         │
│  │ Agent    │      セレクタ修復          │
│  └──────────┘                           │
│                                         │
└─────────────────────────────────────────┘
```

### コンテキストタックスに注意

MCP サーバーを接続するだけで、ツール定義がコンテキストに読み込まれトークンを消費する。これを**コンテキストタックス**と呼ぶ。

```
接続MCPサーバー数    コンテキストタックス
──────────────    ────────────────
1つ               ██░░░░░░░░░░  低い（推奨）
3つ               ██████░░░░░░  中程度
5つ以上            ████████████  高い（要注意）

→ 使わないMCPサーバーは切断しておく
```

## 8. まとめ: チートシート

### やりたいこと別の早見表

| やりたいこと | 使うツール | コマンド / 操作例 |
|:---|:---|:---|
| テスト新規作成 | **MCP + codegen** | MCP で分析 → `npx playwright codegen` |
| テスト実行 | **CLI** | `npx playwright test` |
| デバッグ | **CLI + MCP** | `npx playwright test --debug` / `show-trace` |
| CI/CD | **CLI** | GitHub Actions + `--shard` |
| テスト自動修復 | **Healer Agent** | UI変更検知 → セレクタ自動更新 |
| テスト計画 | **Planner Agent (MCP)** | 自然言語で要件 → 計画書生成 |
| 非技術者向け | **BDD + Allure Report** | `.feature` ファイル + レポート |

### 最終判断フロー（簡易版）

```
Q: AIとの対話が必要か？
│
├── はい → MCP を使う
│          (設計、分析、コード生成、デバッグ支援)
│
└── いいえ → CLI を使う
             (テスト実行、CI/CD、レポート生成)
```

### 覚えておくべき3つのルール

```
┌───────────────────────────────────────────────────┐
```
